## 1. 产品概述

### 1.1 产品定位

一款以 **「输入 → 记忆 → 输出 → 反馈」** 为闭环的英语学习应用。用户通过每日推送发现新内容，整理为个人背诵材料，用记忆卡片巩固记忆，并通过随机口语题进行输出练习。

### 1.2 产品愿景

让学习者用最少操作完成：**每天发现一点新内容、记住该记的、开口练一练**。

### 1.3 核心价值

| 价值 | 说明 |
|------|------|
| 低门槛开始 | 推送即学，一键加入背诵 |
| 科学记忆 | 间隔重复，减少遗忘 |
| 真实输出 | 随机提问 + 录音，练口语而非只看不练 |
| 个人定制 | 用户自主整理，形成专属词库/句库 |

### 1.4 目标用户（MVP 聚焦）

**主用户：日常口语 / 自我提升型学习者**

- 年龄：18–35 岁
- 场景：通勤、碎片时间学习
- 痛点：背了忘、不敢开口、不知道今天学什么
- 英语基础：初级–中级（CEFR A2–B1）

**暂不优先（后续版本）：** 考研/雅思等强考试导向用户

## 2. 产品目标与成功指标

### 2.1 业务目标（上线后 3 个月）

- 次日留存 ≥ 35%
- 7 日留存 ≥ 20%
- 人均每周学习天数 ≥ 3 天
- 口语练习完成率（开始录音并完成保存）≥ 60%

### 2.2 核心行为指标

| 指标 | 定义 | MVP 目标 |
|------|------|----------|
| DAU 学习完成率 | 当日完成「卡片复习 OR 口语一题」的用户占比 | ≥ 50% |
| 卡片掌握率 | 标记为「已掌握」/ 总复习卡片 | 逐周提升 |
| 推送转化率 | 推送内容被「加入背诵」的比例 | ≥ 15% |
| 连续打卡 | 连续学习 ≥ 7 天的用户占比 | ≥ 10% |

## 5. 功能需求详述

### 5.1 模块一：记忆卡片（Flashcards）

#### 5.1.1 功能描述

用户以卡片形式背诵单词、短语、例句等内容；系统按间隔重复算法安排复习。

#### 5.1.2 用户故事

| ID | 用户故事 | 优先级 |
|----|----------|--------|
| F-01 | 作为用户，我想手动创建一张卡片（正面/背面），以便记录我想背的内容 | P0 |
| F-02 | 作为用户，我想从推送/Inbox 一键生成卡片，以便减少录入成本 | P0 |
| F-03 | 作为用户，我想进入「今日复习」按系统推荐顺序背卡片 | P0 |
| F-04 | 作为用户，我想对每张卡片标记「认识 / 模糊 / 不认识」，以便系统安排下次复习 | P0 |
| F-05 | 作为用户，我想切换复习模式（看英想中 / 看中想英 / 听写） | P1 |
| F-06 | 作为用户，我想把卡片分组到不同牌组（如「旅行」「商务」） | P1 |
| F-07 | 作为用户，我想看到卡片的学习状态（新卡 / 学习中 / 已掌握） | P0 |

#### 5.1.3 卡片数据结构

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | string | 是 | 唯一标识 |
| deck_id | string | 是 | 所属牌组 |
| front | string | 是 | 正面（如英文单词/句子） |
| back | string | 是 | 背面（如中文释义） |
| card_type | enum | 是 | word / phrase / sentence |
| audio_url | string | 否 | 发音音频 |
| example | string | 否 | 例句 |
| tags | string[] | 否 | 标签 |
| source | enum | 是 | manual / push / import |
| ease_factor | number | 是 | 间隔重复参数 |
| interval_days | number | 是 | 下次复习间隔 |
| next_review_at | datetime | 是 | 下次复习时间 |
| status | enum | 是 | new / learning / mastered / relearning |

#### 5.1.4 复习流程

```
进入「今日复习」
    → 展示卡片正面
    → 用户点击「显示答案」
    → 用户选择：认识 / 模糊 / 不认识
    → 系统更新间隔与 next_review_at
    → 下一张，直至今日队列完成
    → 展示本次统计（复习数、正确率、明日待复习数）
```

#### 5.1.5 间隔重复规则（MVP 简化版）

| 用户选择 | 间隔变化 |
|----------|----------|
| 不认识 | 重置为 10 分钟后（当日可再次出现）或 1 天 |
| 模糊 | 当前间隔 × 1.2，最短 1 天 |
| 认识 | 当前间隔 × 2.5，按 1→3→7→14→30 天上调 |

#### 5.1.6 验收标准

- [ ] 用户可创建、编辑、删除卡片
- [ ] 今日复习队列仅包含 `next_review_at <= 今日` 的卡片
- [ ] 每次复习后 `next_review_at` 正确更新
- [ ] 复习结束后展示正确率与连续天数
- [ ] 单张卡片复习响应时间 < 200ms（本地缓存命中时）

### 5.2 模块二：随机口语题 + 录音回答（Speaking Practice）

#### 5.2.1 功能描述

系统随机（或按规则）生成英语问题，用户录音回答，可回放；MVP 提供转写文本，V2 提供 AI 反馈。

#### 5.2.2 用户故事

| ID | 用户故事 | 优先级 |
|----|----------|--------|
| S-01 | 作为用户，我想随机获得一道英语问题，以便练习口语 | P0 |
| S-02 | 作为用户，我想按话题/难度筛选问题类型 | P1 |
| S-03 | 作为用户，我想录音回答并限时（如 60 秒/120 秒） | P0 |
| S-04 | 作为用户，我想回放录音对比自己的回答 | P0 |
| S-05 | 作为用户，我想重录覆盖上一次回答 | P0 |
| S-06 | 作为用户，我想看到我的回答被转成文字（ASR） | P1 |
| S-07 | 作为用户，我想看到参考回答或 AI 改进建议 | P2 |
| S-08 | 作为用户，我想在「每日推送」里出现的句子自动生成口语题 | P1 |

#### 5.2.3 问题类型（MVP）

| 类型 | 示例 | 难度 |
|------|------|------|
| 日常问答 | What did you do last weekend? | A2 |
| 观点表达 | Do you prefer working from home or in the office? Why? | B1 |
| 图片描述 | Describe your favorite place to relax. | B1 |
| 跟读/复述 | Read aloud: [推送中的句子] | A2 |

#### 5.2.4 问题生成规则

**MVP：** 从预置题库随机抽取 + 用户已收藏/推送句子的变体题

**V2：** LLM 按用户水平、历史弱项、话题动态生成

生成参数：

| 参数 | 选项 |
|------|------|
| difficulty | A2 / B1 / B2 |
| topic | daily / travel / work / food / custom |
| time_limit_sec | 60 / 120 / 180 |

#### 5.2.5 录音流程

```
点击「开始练习」
    → 展示题目 + 准备倒计时（3 秒）
    → 开始录音（显示计时）
    → 用户点击「完成」或到达时限自动停止
    → 保存录音 → 可选 ASR 转写
    → 回放 / 重录 / 下一题
    → 记录到练习历史
```

#### 5.2.6 录音数据结构

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 唯一标识 |
| question_id | string | 关联题目 |
| user_id | string | 用户 |
| audio_url | string | 录音文件地址 |
| duration_sec | number | 时长 |
| transcript | string | ASR 文本（可选） |
| created_at | datetime | 创建时间 |

#### 5.2.7 验收标准

- [ ] 随机一题响应时间 < 1s
- [ ] 录音可正常开始、停止、回放
- [ ] 支持重录并覆盖
- [ ] 弱网环境下录音本地暂存，恢复网络后上传
- [ ] 用户可查看最近 30 条练习记录

### 5.3 模块三：每日推送 + 内容整理（Daily Push & Inbox）

#### 5.3.1 功能描述

每日向用户推送精选英语内容（句子、表达、短新闻等）；用户可收藏、忽略，或整理进背诵材料（卡片/口语题）。

#### 5.3.2 用户故事

| ID | 用户故事 | 优先级 |
|----|----------|--------|
| P-01 | 作为用户，我想每天收到若干条推送内容 | P0 |
| P-02 | 作为用户，我想对推送「加入背诵 / 收藏 / 忽略」 | P0 |
| P-03 | 作为用户，我想在 Inbox 里统一查看待整理内容 | P0 |
| P-04 | 作为用户，我想从一条推送一键生成单词卡+例句卡 | P1 |
| P-05 | 作为用户，我想从推送生成一道口语练习题 | P1 |
| P-06 | 作为用户，我想设置推送时间（如早 8 点） | P1 |
| P-07 | 作为用户，我想按话题订阅推送类型 | P2 |

#### 5.3.3 推送内容结构

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 唯一标识 |
| title | string | 标题（可选） |
| english | string | 英文正文 |
| chinese | string | 中文翻译 |
| explanation | string | 用法讲解 |
| topic | string | 话题标签 |
| difficulty | enum | A2/B1/B2 |
| audio_url | string | 朗读音频 |
| push_date | date | 推送日期 |

#### 5.3.4 整理工作流

```
每日推送列表
    ├─ [加入背诵] → Inbox（待整理）
    ├─ [收藏]     → 收藏夹（仅浏览，不进复习）
    └─ [忽略]     → 不再展示

Inbox 整理页
    ├─ 生成记忆卡片（选牌组、拆卡规则）
    ├─ 生成口语题
    └─ 标记「已整理」→ 移出 Inbox
```

#### 5.3.5 推送来源（MVP）

| 来源 | 说明 |
|------|------|
| 运营预置内容库 | 初期主要内容来源 |
| 用户收藏句子的复习提醒 | 辅助推送 |

**V2：** RSS/新闻 API、AI 生成、社区UGC

#### 5.3.6 验收标准

- [ ] 用户每日可见固定数量推送（默认 5 条）
- [ ] 「加入背诵」后内容出现在 Inbox
- [ ] 从 Inbox 可成功生成卡片并进入牌组
- [ ] 已忽略内容不再出现在当日列表
- [ ] 推送通知可配置开关与时间

## 7. 核心用户流程

### 7.1 新用户首日流程

```
注册登录
  → 选择英语等级（A2/B1）+ 兴趣话题
  → 引导完成 1 次卡片复习（预置 10 张体验卡）
  → 引导完成 1 次口语录音
  → 展示今日推送
  → 引导将 1 条推送加入 Inbox 并生成卡片
  → 进入首页
```

### 7.2 老用户每日流程

```
打开 App（推送通知）
  → 首页查看今日任务
  → 完成卡片复习
  → 完成 1–3 道口语题
  → 浏览推送，整理 Inbox
  → 查看统计/打卡
```

## 8. 非功能需求

### 8.1 性能

| 指标 | 要求 |
|------|------|
| 首屏加载 | < 2s（4G 网络） |
| 卡片切换 | < 200ms |
| 录音启动延迟 | < 500ms |
| API P95 响应 | < 800ms |

### 8.2 可用性

- 支持 iOS 15+、Android 10+（若以 App 为主）
- 或 Web 响应式（若以 Web MVP 为主）
- 核心学习流程可离线：卡片复习、录音本地保存
- 无障碍：字体大小可调、按钮触控区域 ≥ 44pt

### 8.3 安全与隐私

- 录音默认私有，不上传至公开展示
- 传输 HTTPS；录音存储加密
- 提供隐私政策：数据用途、保留期限、删除方式
- 用户可删除全部录音与学习记录
- 符合 GDPR/个人信息保护法基本要求（若面向国内需做本地化合规）

### 8.4 可靠性

- 服务可用性 ≥ 99.5%
- 录音上传失败自动重试 3 次
- 每日备份用户学习进度

## 10. MVP 范围与版本规划

### 10.1 MVP（v1.0）— 必须有

| 模块 | 功能 |
|------|------|
| 账户 | 注册、登录、基础资料 |

- 导入 Anki/CSV
